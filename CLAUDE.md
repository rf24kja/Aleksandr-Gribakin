# dev24.pro — состояние проекта

Портфолио Александра Грибакина. Живёт на https://dev24.pro, деплой автоматический
из `master` через Vercel. Реклама на сайт **уже идёт**, поэтому сломанное на
проде — это потерянные деньги, а не «поправим потом».

Технические правила проекта — в [AGENTS.md](AGENTS.md). Здесь то, чего в нём нет:
в каком состоянии проект и что осталось.

## Как проверять работу

```bash
npm ci && npm run build && npx playwright test
```

333 теста на трёх движках. Проверено с чистого клона: собирается и проходит
полностью, без единого файла с машины автора.

Перед любым деплоем — полный прогон. После деплоя — проверка живого сайта, а не
локальной сборки: расхождение между ними уже случалось.

## Три правила, которые нельзя нарушать

**1. Ни одной цифры, которую нельзя подтвердить.** С сайта уже удаляли выдуманные
патенты, доклады и «99.99% / 50K/s / 12M+». Все числа в статистике вычисляются из
контента (`src/lib/stats.js`), а не вписываются руками. Цифры в клиентских кейсах —
данные заказчика, и так и подписаны.

**2. Клиентские работы и референсные архитектуры не смешиваются.** Десять кейсов в
`src/data/webProjects.js` — работы для реальных компаний. Семнадцать записей в
`src/data/projects.js` — описания метода, не заказы. Раздел, обещавший заказы и
отдававший метод, — главная причина, по которой сайт читался пустым.

**3. Роли формулируются точно.** У Sixt, 99acres, Properstar и Engel & Völkers —
не «сделал сайт», а конкретный модуль или региональное представительство. Эти
компании имеют свои команды разработки, и завышенная формулировка проверяется в
один звонок.

## Что сделано

- Три режима интерфейса (business / desktop / terminal) над одним набором данных
- 10 клиентских кейсов с графиками «было → стало», объёмом работ и инженерной сложностью
- 17 референсных архитектур
- Раздел «Как я работаю», политика конфиденциальности, чекбокс согласия во всех трёх режимах
- GA4 и Vercel Analytics, метки рекламных кампаний доезжают до письма
- 81 адрес в sitemap, каждый кейс — отдельная индексируемая страница
- Плашки терминала выводятся из таблицы команд, а не ведутся руками: то, что
  есть в `help` и работает без аргумента, само попадает на полосу
- Кофе (USDT TRC-20) во всех трёх режимах, адрес — один, в `src/data/process.js`
